# Changelog

One entry per released tag, grouped by minor. Latest first.

Pre-1.0 the surface is intentionally evolving — every release may
change something operators depend on. Read each entry before
upgrading across more than a few patches at a time. Releases
older than the first structured entry below live in the git log
and on the GitHub Releases page.

## v0.8.x

- v0.8.23 (2026-05-21) — **SLSA L3 provenance, cosign-signed SBOM, ML-DSA-65 sidecar per binary.** Every release now ships a SLSA L3 provenance attestation, a Sigstore-keyless cosign signature over the SBOM (and VEX, when present), and an ML-DSA-65 (FIPS 204) signature sidecar per platform binary for operators with a post-quantum verification posture. The existing GPG, P-384 ECDSA, SHA-256, and SHA3-512 artifacts continue to ship unchanged. **Added:** *Structured `CHANGELOG.md` driven by `release-notes/v<version>.json`* — Every release now lives as a structured JSON entry under `release-notes/`. The workflow renders the GitHub-release-page markdown directly from the JSON, and `CHANGELOG.md` is generated from the full tree via `node scripts/generate-changelog-entry.js --rebuild`. The JSON shape, validator, section-allowlist ordering, and rollup mechanics mirror the upstream blamejs framework's release-notes pipeline. **Changed:** *Vendored blamejs refreshed to v0.11.30* — The pinned upstream version in `vendor/blamejs/` (and `vendor/MANIFEST.json`) advances from v0.11.2 to v0.11.30. The wire-layer surfaces the sync client consumes (`b.wsClient`, `b.httpClient`, `b.pqcAgent`, `b.safeJson`, `b.atomicFile`, `b.retry`, `b.appShutdown`, `b.middleware.apiEncrypt`, ML-KEM-1024 + XChaCha20-Poly1305 envelopes) are byte-identical between the two versions; the refresh picks up upstream additions and security fixes in adjacent modules. **Supply chain:** *SLSA L3 provenance attestation per release* — `hermitstash-sync-vX.Y.Z.intoto.jsonl` is now attached to every release, produced by the `slsa-framework/slsa-github-generator` reusable workflow and signed via Sigstore-keyless. The attestation covers every platform binary plus the SBOM (and VEX when present); operators verify the binary they downloaded was built by this repo's `release.yml` at the matching commit and tag via `slsa-verifier verify-artifact <binary> --provenance-path <jsonl> --source-uri github.com/dotCooCoo/hermitstash-sync --source-tag vX.Y.Z`. · *Sigstore-keyless cosign signature over the SBOM (and VEX)* — `*.cdx.json.sigstore` and (when emitted) `*.vex.json.sigstore` are now attached to every release. Each is a cosign sign-blob bundle binding the SBOM or VEX bytes to the workflow's OIDC identity in the Sigstore transparency log. Verify with `cosign verify-blob --bundle <bundle>.sigstore --certificate-identity-regexp 'https://github.com/dotCooCoo/hermitstash-sync/' --certificate-oidc-issuer 'https://token.actions.githubusercontent.com' <target>`. · *ML-DSA-65 release-signing sidecar (FIPS 204)* — Every platform binary ships an additional `<binary>.mldsa.sig` raw signature alongside the existing P-384 ECDSA `.sig` and armored GPG `.asc`. The release-signing pubkey lives in-tree at `keys/release-pqc-pub.json`; its SHA3-512 fingerprint is recorded in `SECURITY.md` for out-of-band verification. The daemon's auto-update path continues to verify against the embedded P-384 ECDSA pubkey via `node:crypto`; the ML-DSA-65 sidecar is additive for operators with a PQC-only verification posture. · *Tag-matches-VERSION gate in the release workflow* — `.github/workflows/release.yml` now fails the matrix build immediately if the pushed `vX.Y.Z` tag does not match the `VERSION` constant compiled into the SEA binary. A mismatched tag previously produced a binary that reported a different version than the asset name it shipped under.

- v0.8.22 (2026-05-19) — **Systemd unit no longer reports `failure` on graceful SIGTERM.** `deploy/hermitstash-sync.service` now whitelists exit code 143 as a successful shutdown so `systemctl stop hermitstash-sync` reports `inactive (dead)` instead of `failed`. Behaviour of the daemon itself is unchanged. **Fixed:** *`systemctl stop hermitstash-sync` reports `inactive (dead)` on a clean SIGTERM* — The SEA-embedded Node runtime exits with status 143 when the signal handler completes and `process.exit(0)` runs; `tini` (Docker entrypoint) translates it consistently, but the unsupervised systemd unit treated 143 as an abnormal exit. The unit now carries `SuccessExitStatus=143` so a graceful shutdown reaches the dead-active state instead of dead-failed.
